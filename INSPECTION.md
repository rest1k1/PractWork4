# Результат инспектирования чужого PR

Проверен [PR №1 в репозитории GGGLAMKA/PractWork4](https://github.com/GGGLAMKA/PractWork4/pull/1), ветка `feature`, база `main`.

## Проверка реализации

Метод `FilterAndSort` находится в отдельном `NotificationService`. В обычных сценариях реализованы фильтры по `IsRead`, типу, тексту и минимальному приоритету, а также сортировка по дате, приоритету и заголовку. Проверка `notifications == null` предусмотрена. При `options == null` метод возвращает исходную последовательность без фильтрации и сортировки; такое поведение стоит явно согласовать с требованиями.

## Замечания

1. **Низкая важность — лишнее использование `IQueryable`.** В `NotificationService.cs`, строки 30–31, `IEnumerable` переводится в `IQueryable` с комментарием об оптимизации. Для переданной последовательности это не обеспечивает оптимизацию и усложняет код; достаточно использовать LINQ для `IEnumerable`.
2. **Низкая важность — невалидное значение сортировки молча игнорируется.** В `NotificationService.cs`, строки 64–80, значение `SortBy`, не соответствующее членам enum, попадает в `_ => query`, поэтому результат возвращается без сортировки и без сообщения об ошибке. Рекомендуется явно определить поведение для такого значения.
3. **Замечание по сопровождению репозитория — в PR попали генерируемые и посторонние файлы.** Из 20 изменённых файлов 12 относятся к `.vs`, 2 — к `obj`, а также добавлен `3131.txt`. Кэш IDE и сгенерированные файлы не нужны в исходниках; следует исключить их через `.gitignore`. `3131.txt` следует удалить, если он не относится к заданию.
4. **Тестируемость не подтверждена тестами.** В PR не добавлен тестовый проект или тесты для комбинаций фильтров, сортировки по возрастанию/убыванию и граничных значений. Сам метод не зависит от внешних сервисов и в целом легко тестируется.

## Архитектура и SOLID

Отдельный сервис с одной задачей соответствует принципу единственной ответственности. Другие принципы SOLID здесь выражены ограниченно: например, добавление новых вариантов сортировки потребует изменять `switch`, но для объёма задания отдельные стратегии не обязательны.

## Итог

Основные фильтры и варианты сортировки реализованы. Критических логических дефектов при обычных допустимых входных данных не выявлено. Перед слиянием рекомендуется убрать IDE/build-артефакты и посторонний текстовый файл; также стоит добавить тесты и определить поведение для невалидного значения `SortBy`.
